# All Video Downloader

تطبيق Android أصلي بـ Kotlin وJetpack Compose وMaterial 3 لتحليل روابط الوسائط وتنزيل المحتوى المسموح به محليًا على الجهاز باستخدام yt-dlp.

> استخدم التطبيق فقط مع المحتوى الذي تملكه أو لديك إذن صريح من صاحب الحقوق والمنصة بتنزيله. التطبيق لا يتجاوز DRM، ودعم المواقع قد يتغير عندما تغيّر المنصات آلياتها.

## المزايا

- تحليل روابط YouTube وFacebook وInstagram وX/Twitter وTikTok وغيرها داخل الهاتف.
- عرض قائمة مختصرة من جودات MP4 الفعلية، بجودة واحدة فقط لكل دقة ومن دون تكرارات WEBM/MP4.
- تنزيل فيديو MP4 أو صوت M4A ‏(AAC)؛ يُحوّل الصوت داخل الهاتف عبر Google Media3 Transformer.
- لا يتضمن التطبيق FFmpeg أو aria2؛ وعند اختيار فيديو ذي مسارين يدمجهما Android MediaMuxer محليًا.
- طابور تنزيل دائم بعمليات: إيقاف مؤقت، استئناف، إلغاء، وإعادة محاولة.
- خدمة أمامية مستقلة للتنزيلات الطويلة مع إشعار تقدم وأزرار تحكم وإشعار انتهاء أو فشل.
- مجلد مؤقت مستقل لكل عملية لمنع اختلاط نتائج التنزيلات المتزامنة.
- حفظ آمن عبر MediaStore داخل:
  - `Movies/<اسم المجلد>` للفيديو.
  - `Music/<اسم المجلد>` للصوت.
- لا توجد صلاحية `MANAGE_EXTERNAL_STORAGE` ولا صلاحيات تخزين قديمة.
- سجل تنزيلات محلي، تشغيل داخل التطبيق عبر Media3، ومشاركة الملف الناتج.
- إعداد Wi-Fi فقط، اسم مجلد مخصص، طريقة تسمية الملفات، سمة داكنة، وألوان ديناميكية.
- استيراد اختياري لملف `cookies.txt` عبر منتقي ملفات النظام؛ يُنسخ إلى التخزين الخاص ولا يتطلب صلاحية إدارة ملفات.
- استقبال الروابط في نافذة Material 3 عائمة ومختصرة، بحيث يبقى التطبيق الذي تمت المشاركة منه ظاهرًا خلفها.
- واجهة إنجليزية وعربية مع دعم RTL.
- لا توجد Telemetry أو تحليلات أو تحديث ذاتي للشيفرة التنفيذية.

## التوافق مع Code on the Go

ضُبط المشروع خصيصًا لنسخة **Code on the Go C-r-0815-1546** ضمن الحدود الموثقة للمحرر:

| المكوّن | الإصدار |
|---|---:|
| Android Gradle Plugin | 8.11.0 |
| Gradle Wrapper | 8.13 |
| Kotlin | 1.9.22 |
| Java source/target | 17 |
| compileSdk / targetSdk | 36 |
| minSdk | 29 |
| معماريات APK | armeabi-v7a, arm64-v8a |

يفتح المحرر المشروع كمشروع Gradle موجود. لا ترفع AGP إلى 9.x في هذه النسخة من المحرر. يستخدم Code on the Go ‏JDK 21، بينما يطلب المشروع صياغة Java 17، وهذا متوافق.

### البناء على الهاتف

1. استنسخ المستودع أو افتح مجلد المشروع في Code on the Go.
2. اترك أول Gradle Sync يكمل تنزيل الاعتماديات.
3. تأكد من تثبيت Android SDK Platform 36 داخل المحرر.
4. شغّل مهمة `assembleDebug` أو نفّذ من الطرفية:

```bash
./gradlew :app:assembleDebug
```

ينشئ Gradle ملفًا مستقلًا لكل معمارية لتجنب APK ضخم يجمع مكتبات جهازين معًا:

```text
app/build/outputs/apk/debug/app-arm64-v8a-debug.apk
app/build/outputs/apk/debug/app-armeabi-v7a-debug.apk
```

استخدم `arm64-v8a` للهواتف الحديثة (ومنها الجهاز الظاهر في سجل المشكلة)، واستخدم `armeabi-v7a` فقط لهاتف 32 بت قديم. يرفع GitHub Actions الملفين كقطعتين منفصلتين كي لا تضطر لتنزيل APK عالمي يتجاوز حجمه الحاجة الفعلية.

يحتاج أول Gradle Sync إلى مساحة كافية لتنزيل Android Gradle Plugin وAndroidX ومحرك yt-dlp. لم يعد FFmpeg أو aria2 جزءًا من الاعتماديات.

## الصلاحيات

| الصلاحية | السبب |
|---|---|
| `INTERNET` | تحليل الرابط وتنزيل الوسائط |
| `ACCESS_NETWORK_STATE` | الانتظار عند انقطاع الشبكة وتطبيق Wi-Fi فقط |
| `WAKE_LOCK` | منع نوم المعالج أثناء عملية تنزيل نشطة فقط؛ صلاحية عادية بلا نافذة موافقة |
| `POST_NOTIFICATIONS` | عرض تقدم التنزيل على Android 13+؛ تُطلب عند بدء أول تنزيل فقط |
| `FOREGROUND_SERVICE` | إبقاء التنزيل الذي بدأه المستخدم نشطًا |
| `FOREGROUND_SERVICE_DATA_SYNC` | نوع الخدمة الأمامية المطلوب على Android الحديث |

لا يطلب التطبيق `READ_MEDIA_*` لأنه لا يفحص مكتبة المستخدم، ولا يطلب `WRITE_EXTERNAL_STORAGE` لأن الحد الأدنى Android 10 والحفظ يتم من خلال MediaStore.

## البنية

- `data/YtDlpRuntime.kt`: تهيئة yt-dlp خارج الـ main thread وإدارة ملف Cookies الخاص.
- `data/YtDlpExtractor.kt`: تحليل الرابط وتحويل الجودات إلى نماذج واضحة.
- `data/AppRepository.kt`: إعدادات وسجل محليان عبر DataStore.
- `download/DownloadService.kt`: الطابور، التحكم بالعمليات، الاستمرار، والإشعارات.
- `download/OnDeviceMediaProcessor.kt`: تحويل الصوت إلى M4A عبر Media3 ودمج مسارات MP4 عبر Android MediaMuxer.
- `download/MediaStoreWriter.kt`: نشر الملف النهائي بأمان باستخدام `IS_PENDING`.
- `ui/`: شاشات الرئيسية والتنزيلات والإعدادات والمشغل بـ Material 3.

## التحقق

يشغّل GitHub Actions تلقائيًا:

```bash
./gradlew :app:assembleDebug :app:assembleRelease :app:testDebugUnitTest :app:lintDebug
```

ثم يفحص سير العمل محاذاة مكتبات ELF ذات 64 بت لصفحات 16KB، ويتأكد من عدم رجوع مكتبات FFmpeg أو aria2 إلى APK. تغطي اختبارات الوحدة تنقية الجودات ومنع التكرار، اختيار صيغة yt-dlp، تنظيف الأسماء، MIME types، استخراج الروابط، وحفظ/استعادة سجل التنزيلات.

## قيود معروفة

- دعم أي منصة ليس عقدًا ثابتًا؛ قد تتطلب بعض الروابط جلسة مستخدم صالحة أو قد تتوقف مؤقتًا بعد تغيير الموقع.
- التطبيق لا يسجّل الدخول نيابة عن المستخدم. يمكن للمستخدم استيراد ملف Cookies يخصه، وهو مسؤول عن حمايته وصلاحيته.
- إيقاف التنزيل مؤقتًا يحافظ على الملفات الجزئية ويحاول yt-dlp إكمالها عند الاستئناف، لكن بعض الخوادم لا تدعم الاستكمال.
- خدمات `dataSync` الأمامية لها حدود زمنية على إصدارات Android الحديثة؛ عند بلوغ مهلة النظام تُحفظ العملية كفاشلة ويمكن إعادة المحاولة.
- نشر تطبيق تنزيل عام على Google Play قد يتطلب مراجعة قانونية وسياساتية دقيقة لكل منصة وحقوق المحتوى.
